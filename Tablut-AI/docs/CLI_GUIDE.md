# Human vs AI：终端人机对战指南

v2.2 第一阶段提供命令行人机对战。你选择一方，另一方由现有 AI 控制，实际移动、捕获和终局均交给老师未修改的 `reference/Tablut.py` 执行。

## 启动

在 `Tablut-AI/` 目录运行：

```powershell
python scripts/play_cli.py --side A --strategy adaptive
```

选择防守方，让 AI 先走，并显示搜索信息：

```powershell
python scripts/play_cli.py --side D --strategy minimax --show-search
```

省略 `--side` 时，程序会询问 A 或 D，也可输入 `quit` 退出。

| 参数 | 含义 |
| --- | --- |
| `--side A` / `--side D` | 人类身份；A进攻，D防守并控制国王 |
| `--strategy` | AI策略，默认adaptive；还支持first、random、greedy、minimax |
| `--seed` | Random策略的随机种子，默认42 |
| `--show-search` | 开启本步监控并打印实际搜索统计 |
| `--help` | 查看启动参数 |

这些策略是实验选项，没有足够数据保证 Adaptive 一定比 Minimax 更强。

## 棋盘和坐标

终端显示完整9×9棋盘。列使用 A–I，行使用1–9；坐标先写列、再写行：

| 用户输入 | 内部坐标 `[row, column]` |
| --- | --- |
| A1 | `[0,0]` |
| D1 | `[0,3]` |
| E5 | `[4,4]`，中心城堡 |
| I9 | `[8,8]` |

棋盘中的 `A` 是攻击者，`D` 是防守者，`K` 是国王，`.` 是普通空格，`X` 是空城堡。列名A与攻击棋子A是两个不同的标记，注意结合表头和格子内容阅读。

进攻方总是先行动。你选择 `--side D` 时，应先等待 AI 走完第一步。

## 如何下棋

轮到你时，输入起点和终点，中间用空格分隔。例如初始局面中，攻击棋子从D列第1行向左走一格：

```text
D1 C1
```

大小写不敏感，`d1 c1` 也可使用。不要输入从0开始的行列数字，也不要用逗号或箭头代替空格。

输入通过检查后才会交给裁判。输入错误、棋盘外坐标、移动对方棋子、落到被占据格、斜走或越子都应得到提示，棋盘和行动方保持原样，可重新输入。

| 游戏内命令 | 作用 |
| --- | --- |
| `help` | 显示输入格式和命令 |
| `moves` | 显示当前人类一方的合法走法 |
| `board` | 重新显示棋盘 |
| `quit` | 主动中止，不算平局 |

每个成功执行的动作后，程序会显示新棋盘；AI 行动时还会显示动作和耗时。

## 本项目规则摘要

以下用于帮助操作，正式规则以课程原文及老师裁判为准：

- 普通棋子及国王沿横向或纵向滑动，不能越过其他棋子，也不能落在被占据格。
- 国王离开中心后留下 `X`。空城堡可以被经过，但不能作为落点。
- 普通棋子通常通过两侧夹击捕获；国王在中心或邻近中心时有特殊围捕规则。
- 国王到达棋盘任意边缘，或进攻棋子少于两枚时，防守方获胜；国王被捕时进攻方获胜。
- 当前行动方没有合法走法，或同一棋盘且同一行动方再次出现时，裁判判平局。国王没有逃出或被捕也可能已结束。

## 时间与搜索信息

人类输入和思考不计入比赛预算。AI 仍使用原有 TimeManager，并由 CLI 在每次决策返回后检查其整局累计决策耗时是否超过60秒；计时不包括人类输入、棋盘展示和帮助命令。

使用 `--show-search` 可以查看目标深度、完整完成深度、Alpha-Beta递归节点、实际耗时、深度选择/停止原因和截止回退。没有提供统计时明确显示未记录。

First 和 Random 深度为0；Greedy 正常完成一层时为1；Minimax目标2；Adaptive按已有条件目标2或3。直接发现一步获胜时目标1、完成0，表示未扫描完整层就已找到胜利动作，不代表没有评估行动。节点不包含Greedy首层扫描。

CLI属于本地交互体验，不是正式联赛Performance证明；AI截止检查是协作式的，不能在单次底层计算中强制终止。

## 结束、中止和出错

- 正常胜负或平局：显示最终棋盘及官方结果。
- 输入 `quit`、关闭输入流（EOF）或按 Ctrl+C：显示中止，赢家为空，不记录为平局。
- AI抛出异常、返回非法动作或累计超时：明确报告原因，AI判负，人类获胜；进程以非零退出码结束，便于发现程序问题。
- 如果出现内部裁判或工具一致性错误，程序应报告错误，不能把它冒充正常平局。

当前阶段不写入 `reports/human_games/`，也不导出JSON棋谱或HTML。已有 `replay_demo.py` 只生成内置AI互相对战的棋谱；人机棋谱集成留作第二阶段。

## 常见问题

**输入E1 E2为什么不合法？** 初始E2已经有攻击棋子，不能作为落点。建议先输入 `moves` 查看当前合法动作；初始进攻方可使用 `D1 C1` 验证输入流程。

**我选D为什么不能先输入？** A必须先行，此时先由AI完成进攻动作。

**棋盘没有出现获胜画面，却停止了？** 查看最后输出。重复局面或无合法行动也会判平局；退出、EOF与Ctrl+C则为中止。

**怎样确认程序正常？** 执行 `python -m unittest discover -s tests -v`。原有规则、搜索、外部Bot及回放测试继续保留，CLI边界使用模拟输入和AI对象单独测试。

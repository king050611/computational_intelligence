# Evolutionary Dynamic V4：搜索效率、30 局复筛与首次正向验证

实验日期：2026-11-27。基准提交 `449fe2bc335aea0a392ebdf63d64b0167bbccb73`（V4 为未提交的本地修改）。

## 0. 一句话结论

引擎快了 **3.8 倍**、平均完成深度从 3.1 升到 **3.77–3.92**，30 局复筛让一个**新权重首次超过手工基线**
（60.0% vs 50.0%）；40 局独立验证对新模型有利（**61.25%**，净胜 9 局），但配对区间下限正好 50.0%、
样本未达 60 局，**未达晋级条件，正式 Bot 保持不变**。

## 1. 结论摘要

V3 复盘指出两个比种群重复更根本的问题：**同一权重跨运行漂移 12/24–16/24**、**深度 2 快筛与深度 4 复筛排名零相关**。
V4 针对这两点先动引擎与评估机制，不动规则、裁判、六特征与正式入口。

| 指标 | V3 基线 | V4 | 变化 |
| --- | --- | --- | --- |
| 初始局面深度 3 搜索耗时 | 1.10s | **0.20s** | −82% |
| 同局面节点数（深度 3） | 13,515 | **9,423** | −30% |
| 节点速度 | 12.3k nodes/s | **46.6k nodes/s** | **3.8×** |
| `apply_move`（含合法性校验） | 27 µs | **3.1 µs** | 8.7× |
| `check_winner` | 26 µs | **5.0 µs** | 5.2× |
| `extract_features` | 25 µs | **6.9 µs** | 3.6× |
| 正式对局平均完成深度 | 3.1 | **3.77–3.92** | 达成方案 ≥3.5 目标 |
| 复筛每人局数 | 12 | **30** | 2.5× |
| 复筛中的新权重数 | 2 | **3** | +1 |
| 单元测试 | 87 | **101** | +14 |

方案 §5.2 的工程目标是「固定深度耗时 −20%~40%、同时间节点数 +30%」，实测分别达到 −82% 与 +279%，超出目标。
固定深度分数与 V3 **完全一致**（24 个局面 × 深度 2/3，零差异，见 §3）。

训练与验证的核心数字：

| 阶段 | 结果 |
| --- | --- |

| 复筛（深度 4，每人 30 局，共 120 局） | **i7 36/60 = 60.0%**，手工基线 30/60 = 50.0%，V2 邻域权重 22/60，另一新权重 13/60 |
| 独立验证（40 局，全新 20 对开局） | i7 对现役正式 Bot **18W13D9L，49/80 = 61.25%**，配对 95% 区间 [50.0%, 72.5%] |
| 违规 | 训练 152 局、验证 40 局，非法走法/超时/异常/非法返回全部为 0 |


## 2. 引擎改动明细

### 2.1 消除重复生成（`src/game.py`）

| 原实现 | V4 实现 |
| --- | --- |
| `apply_move` 用 `move in get_legal_moves(board, player)` 校验合法性 → **每个节点一次完整走法生成** | `is_legal_move`：校验归属、终点为空、同行同列且中途格全为 `.`/`X`，O(路径长度) |
| 终局判定里的“无合法走法”同样生成全部走法 | `has_any_move`：扫到第一条可走路径即返回，O(81) 最坏 |
| 特征里的“逃生路线”生成守方全部走法 | `get_piece_moves`：只生成国王自己的走法 |

`get_piece_moves`、`has_any_move`、`is_legal_move` 与 `get_legal_moves` 的等价性由 `tests/test_search_v4.py` 在随机局面上逐一核对（含跨城堡通行、城堡不可停留、无子可动判和）。

### 2.2 置换表（`src/transposition.py`、`src/enhanced_search.py`）

V3 的置换表只存“深度 + 走法提示”，不缓存分数（当时是为避免重复历史污染）。V4 改为缓存分数，但加三条硬约束：

1. **上下界按进入节点时的原始窗口判定**。实现过程中先写成了用循环中被抬高的 `alpha` 判定，导致几乎所有条目被存成 `UPPER`、缓存完全不命中（`hits=0`，`probe` 返回 `None`）。该缺陷由新测试 `test_repetition_draw_is_never_cached`/`test_table_scores_match_plain_search` 直接暴露，修复后才获得下面的加速。
2. **子树出现过重复局面则不入表**：`repetition_hits` 计数在节点前后比较，任何重复和棋都会放弃写入，因为和棋分数依赖祖先历史。
3. **节点自身已在 `history` 中就直接返回和棋分数**，不查表。

### 2.3 走法排序（实测选择，不是拍脑袋）

对同一批局面（初始 + 2 个中局）做固定深度对照，节点数与耗时：

| 排序方案 | 深度 3 节点/耗时 | 深度 4 节点/耗时 |
| --- | --- | --- |
| 不排序 | 123,180 / 2.56s | 1,316,327 / 42.18s |
| 仅置换走法 | 59,126 / 1.59s | 504,694 / 17.46s |
| 置换 + killer + history | 32,981 / 0.95s | 126,100 / 5.11s |
| **置换 + killer + 王逃生** | **32,659 / 0.83s** | **125,203 / 4.98s** |
| 置换 + killer + 王逃生 + 相邻敌人集合（V3 项） | 34,304 / 1.10s | 133,154 / 5.62s |

结论：V3 的“相邻敌人集合”项要每节点额外 O(81) 扫描，却让节点数增加 6%、耗时增加 13%，已删除。
最终排序键为：根优先 > 王逃生 > 置换走法 > killer > history。

### 2.4 固定节点预算（实验模式）

`SearchOptions(node_budget=N)` 与 `benchmark.py --node-budget N`：每步在固定节点数处停止，战术诊断也改为按生成子节点数
（`max_nodes=200`）而不是 10ms 计时，因此**同局面同历史必得同一走法**（`test_fixed_node_budget_is_deterministic`
断言两次运行节点数、完成深度、走法完全相同）。正式比赛仍使用 60 秒墙钟。

## 3. 正确性验收

1. **全量测试**：101 项通过（原 87 + V4 新增 14），5.9s。
2. **跨版本固定深度对照**：把 V3 引擎（`reports/training/v3_baseline_archive/engine/`）与 V4 引擎分别作为独立进程，
   在 24 个局面（12 个开局方 + 12 个应手方）上比较深度 2、深度 3 的最优分数：**0 处差异**。
3. **纯搜索 vs 缓存搜索**：随机局面上 `tt_capacity=0/不排序` 与 `tt_capacity=20000/排序` 的分数逐一相等。
4. **重复历史**：带重复历史的查询返回和棋分，且不会覆盖同局面在干净历史下的分数。
5. **等价性**：`is_legal_move` 与 `move in get_legal_moves` 在 12 个局面 × 全 9×9×9×9 候选上完全一致；`has_any_move` 与 `bool(get_legal_moves)` 一致。

### 5.1 三个值得记录的观察

1. **搜索深度达到方案目标**：平均完成深度 3.82（V3 为 3.1，方案目标 ≥3.5）。但平均每步只用了 0.68–0.78s，
   远低于 AdaptiveTimeManager 给出的约 1.3s 预算——**深度 4 现在能在预算内跑完，剩余时间被浪费**。
   下一轮应把 `max_depth` 提到 5（或改成“预算内尽量加深”），这是最直接的剩余收益点。
2. **快筛（深度 3）这次预测对了第一名**：i7 快筛第 1（75%）、复筛第 1（60%）；四个入围者的 名次相关（Spearman）
   为 0.4，而 V3 的深度 2 快筛是 0.0。样本只有 4 个候选，只能说“深度 3 没有出现 V3 那种反向”，不能当作稳定结论。
3. **攻守仍不平衡**：冠军执攻 43.3%、执守 76.7%（V3 冠军为 41.7%/58.3%）。守方能力提升明显，攻方仍是短板，
   与方案 §8 的假设一致，但样本是 15 局/方。

### 5.2 时间与稳定性

152 局（32 快筛 + 120 复筛）聚合：`illegal_moves=0, timeouts=0, exceptions=0, invalid_returns=0`；
单方最高累计 **54.986s / 60s**。训练总用时 87.6 分钟（07:22–08:50）。

## 8. 结论与决策

| 晋级条件（方案 §10） | 要求 | 本轮结果 | 判定 |
| --- | --- | --- | --- |
| 官方积分率 | ≥55% | **61.25%** | ✅ |
| 配对 95% 区间下限 | >50% | **50.0%** | ❌（恰好等于 50%，未严格高于） |
| 独立正式验证局数 | ≥60 | 40 | ❌（这是 Phase 2 初探，不是正式验证） |
| 非法走法 / 超时 / 异常 | 0 | 0 | ✅ |
| 平均完成深度 | ≥3.5 | 3.772 | ✅ |

**决策：不替换正式参赛模型。** 本轮首次拿到正向信号（同一批独立开局上，新模型对现役正式 Bot 净胜 9 局），
但配对区间下限正好落在 50%、样本只有 40 局，按方案只有满足全部条件才允许晋级。

**下一步（按性价比排序）**

1. **60 局正式验证**：另取 30 对全新开局，跑 i7 vs 现役正式 Bot。若下限 >50% 且积分率 ≥55%，再谈替换。
2. **提高深度上限**：冠军平均每步只用 0.68–0.82s，而单步预算是约 1.3s，深度 4 已能在预算内跑完，
   剩余时间被浪费。把 `max_depth` 提到 5（或改为“预算内持续加深”）是最直接的剩余收益。
3. **攻方专项**：复筛中冠军执攻 43.3%、执守 76.7%；验证中攻 55.0%、守 67.5%。守方已强，攻方是短板，
   可优先分析攻方未胜的棋谱（方案 §8 的八项检查），再决定是否新增攻方特征或调整奖励。
4. **新评估特征**（Phase 4）：仍未实现，理由见 §9。

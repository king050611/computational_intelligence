# V6 Phase 3 实施与实验记录

开发基准为 87e3119。冻结引擎与模型位于 engines 和 models。每组 manifest 记录引擎文件哈希、模型哈希、裁判哈希、开局、深度及时间和节点预算。候选使用迁移后的八维 V4 冠军。四个专项模型是预设实验权重。

生成器支持单独指定候选及对手源码、模型、深度、节点与时间预算。对局逐局通过课程规则重放后原子保存，恢复前核对配置并重验已有棋谱。串行运行正式计时对照。只有两方都固定节点时才允许多个比赛进程，并限制并发数。

运行全矩阵使用 python -u -m scripts.run_phase3。默认 120 局版本与搜索对照加 80 局专项压力测试。增强、封锁、逃生、保护四组压力测试分开统计。原有赛果与留出集保留。阶段汇总可运行 python -m scripts.analyze_phase3，合并后的有效棋谱副本和分组指标是当次快照。标准时限与高预算组各自统计。

## 已验证的内容

- 冻结 V3 对冻结 V4 的两局低深度冒烟测试通过，已验证从完整输出恢复时跳过已有对局。
- 249 个可重建的合成战术局面中，双步围捕有 9 个，其余八类各 30 个。每个样本保留从初始棋盘开始的合法走法。双步围捕逐一核对守方合法应手。优势和劣势依据静态分数分桶，强制和棋走法由规则确认。
- 新增三项回归，校验可达性和对称去重、历史立即取胜、历史安全替代。安全替代验证中，四个可用开发样本在深度 2 下均避免下一步直接败局。
- 双路逃生和城堡附近围捕的战略设计参考 [Ashton 的规则研究](https://www.jemne.org/issues/13/ashton.php)。样本标签由课程规则检验。
